# 版本发布说明管理台

管理版本发布记录和变更说明。面向本地单机使用，仅依赖 Python 3 标准库与
内置 SQLite，无需安装任何第三方包，也无需联网。

当前实现的是最小草稿功能：创建版本草稿、按版本名查看草稿、查看全部草稿
的版本名与标题目录、修订已有草稿的标题、向已有草稿追加变更、替换已有
草稿中的单条变更、删除已有草稿中的单条变更、移动已有草稿中的单条变更，
重命名已有草稿的版本名，复制已有草稿（保留原版本并以新名称再整理一
份），把单个草稿按固定 Markdown 格式导出到标准输出，以及按目录顺序把
多份草稿汇总成一份 Markdown 导出到标准输出。暂不支持分类、发布或 Git
相关操作。

## 入口

命令行入口为 `release_notes.py`，所有操作都通过 `--db` 指定同一个
SQLite 数据库文件。首次有效创建时若该文件不存在会自动建立数据库，之后
的进程使用同一路径即可继续读取与追加。

### 创建草稿

```
python release_notes.py --db notes.sqlite create <版本名> --title <标题> --change <变更> [--change <变更> ...]
```

- 每份草稿至少包含一条变更；`--change` 可重复传入，条目按传入顺序保存，
  重复内容分别保留。
- 版本名、标题、变更文本原样保存：中文、标点、首尾空格及文本内部换行都
  保留，不自动裁剪或转义。
- 版本名按原文精确匹配，区分大小写。
- 成功时退出码为 0，标准输出为 `Created <版本名>`。
- 以下情况退出码为 1，标准错误输出 `Invalid draft`，且不会创建文件或
  留下部分草稿：
  - 未提供变更，或版本名、标题、任一变更为空 / 仅由空白组成。
- 版本名已存在时，退出码为 1，标准错误输出
  `Version already exists: <版本名>`，不覆盖旧标题或条目。

### 查看草稿

```
python release_notes.py --db notes.sqlite show <版本名>
```

- 成功时退出码为 0，依次输出版本、标题和每条变更：

  ```
  Version: <版本名>
  Title: <标题>
  - <变更 1>
  - <变更 2>
  ```

- 多行变更仍是一条记录，展示时在首行前加 `- `，内部换行原样保留。
- 版本不存在（数据库文件尚不存在、库中没有 drafts 表或查无该版本）时，
  退出码为 1，标准错误输出 `Version not found: <版本名>`；只读查看不会
  补建 drafts 或 changes 表，也不改动库中其他表与数据。

### 查看全部草稿

```
python release_notes.py --db notes.sqlite list-drafts
```

- 只读目录查询：成功时退出码为 0，标准错误为空，标准输出是一个 UTF-8
  JSON 数组，末尾恰有一个换行，没有提示语或其他内容。每个元素只包含
  `version` 和 `title` 两个字符串字段，分别对应当前保存的版本名与标题，
  不包含变更条目。
- 版本名与标题按原文输出：中文等非 ASCII 字符直接输出，引号、反斜杠
  和控制字符按 JSON 规则转义，解析后与数据库原文完全一致，首尾空格与
  内部换行均不裁剪。
- 数组按版本名原文的 Unicode 码点逐字符升序排列，前缀相同时较短名称
  在前；不按语义版本号、创建顺序或标题排序，也不合并大小写不同的名称。
- 指定数据库文件不存在，或已有数据库中没有草稿时，同样退出 0、标准
  错误为空，只输出 `[]` 和末尾换行，且不创建数据库文件。
- 查询不改变任何草稿与变更的原文、条目数量或展示顺序，也不创建其他
  文件；数据未变化时，另一个进程使用同一路径查询得到相同数组。用
  `set-title` 修改标题后，再次查询即显示新标题。

#### 按版本名前缀筛选

```
python release_notes.py --db notes.sqlite list-drafts --prefix v1
```

- 在 `list-drafts` 后追加可选的 `--prefix <文本>` 时，仅返回版本名原文
  以该文本开头的草稿；标题与变更内容不参与匹配。省略该选项时保留列出
  全部草稿的行为。
- 匹配区分大小写，不解析语义版本，前缀不裁剪：中文、首尾空格与内部换行
  均按原文逐字符比较，`%` 和 `_` 是普通字符而非通配符。输出格式、排序
  规则（版本名 Unicode 码点升序）与不带筛选时完全一致；没有匹配项、
  数据库路径不存在、库中没有草稿表或表中没有草稿时，都只输出 `[]` 和
  末尾换行，不创建数据库或补建表。
- 显式提供 `--prefix` 却没有值、值为空或仅含空白、重复提供该选项时，
  退出码为 1，标准输出为空，标准错误仅输出 `Invalid draft` 和一个换行；
  即使数据库文件不存在，也优先返回此错误。

### 导出 Markdown

```
python release_notes.py --db notes.sqlite export-markdown <版本名>
```

- 只读导出：结果只写到标准输出，供查看或由终端重定向保存；命令不接收
  输出路径，不创建任何发布说明文件，草稿内容在导出前后保持不变。
- 版本名按原文精确匹配，区分大小写。成功时退出码为 0，标准错误为空，
  标准输出恰为如下固定格式：先拼接 `# `、版本名原文和两个换行，再拼接
  标题原文和两个换行，最后按 `show` 的展示顺序为每条变更原文加上
  `- ` 前缀并各接一个换行：

  ```
  # <版本名>

  <标题>

  - <变更 1>
  - <变更 2>
  ```

- 版本名、标题与每条变更均按原文拼接，不转义、不整理空白：中文、标点、
  Markdown 字符、首尾空格及内部换行都保留；版本名或标题中的换行同样
  保留；多行变更只在首行前加 `- `，内部换行原样输出；重复文本作为不同
  条目分别输出。
- 版本名为空或仅由空白组成时，退出码为 1，标准错误输出 `Invalid draft`；
  即使数据库文件尚不存在，也优先返回这一结果。
- 输入有效但数据库文件不存在、库中没有 drafts 表（完全空库或只有无关
  表），或查无对应版本时，退出码为 1，标准错误输出
  `Version not found: <版本名>`。
- 以上失败的标准输出均为空，错误消息末尾带换行；不会创建数据库文件，
  不补建 drafts / changes 表，也不改动库中其他表与数据。连续导出或新
  进程使用同一路径导出的文本完全一致。

### 汇总导出 Markdown

```
python release_notes.py --db notes.sqlite export-changelog
python release_notes.py --db notes.sqlite export-changelog --prefix <文本>
```

- 只读汇总当前保存的全部草稿，不区分发布状态，也不解析语义版本号。
  省略 `--prefix` 时汇总全部草稿；追加可选的 `--prefix <文本>` 时只
  汇总版本名原文以该文本开头的草稿。前缀的匹配规则与 `list-drafts
  --prefix` 完全一致：只匹配版本名，区分大小写、不裁剪空白，`%` 和 `_`
  是普通字符而非通配符，标题与变更不参与匹配。
- 选中哪些草稿、按什么顺序排列，与同一数据库上相同筛选条件的
  `list-drafts` 完全一致：按版本名原文的 Unicode 码点逐字符升序，前缀
  相同时较短名称在前。每份草稿按当前展示顺序输出条目，多行变更仍是
  一条记录。
- 成功时退出码为 0，标准错误为空，标准输出只包含 UTF-8 Markdown：
  每份草稿的片段逐字等同于对该版本执行 `export-markdown` 的成功输出；
  相邻片段之间额外插入恰好一个换行（片段本身已以一个换行结尾），最后
  一份之后不追加任何内容。版本名、标题和变更中的中文、标点、Markdown
  字符、首尾空格及内部换行均原样保留，不去重、不整理文本，重复条目
  分别出现。例如库中有 v1（两条相同变更）与 v2 时，先完整输出 v1 的
  片段再输出 v2 的片段；`--prefix v2` 时只输出 v2 的片段，与单份导出
  完全相同。
- 显式提供 `--prefix` 却没有值、值为空或仅含空白、重复提供该选项时，
  退出码为 1，标准输出为空，标准错误仅输出 `Invalid draft` 和一个换行；
  该校验优先于数据库读取，即使数据库文件不存在，也优先返回此错误且
  不创建任何文件。
- 输入有效但没有匹配项、数据库文件不存在、库中没有 drafts 表（完全
  空库或只有无关表），或草稿表为空时，统一退出码为 0，标准输出与
  标准错误都为空（不输出换行或其他内容）。
- 汇总导出不创建数据库、不补建表、不生成输出文件，也不改动其他表；
  已有草稿的名称、标题、条目数量与顺序保持不变。命令不接收输出路径，
  需要保存时由终端重定向；另一个进程使用同一路径汇总得到完全一致的
  文本。

### 修订草稿标题

```
python release_notes.py --db notes.sqlite set-title <版本名> --title <新标题>
```

- 只修改标题：版本名与每条变更的原文、数量、顺序均保持不变。
- 新标题按输入原样保存：中文、标点、首尾空格及内部换行都保留，不自动
  裁剪或转义。版本名按原文精确匹配，区分大小写。
- 成功时退出码为 0，标准输出为 `Updated title: <版本名>`。再次提交同一
  标题也按成功处理，不会新增草稿或变更条目。
- 未提供 `--title`，或版本名、新标题为空 / 仅由空白组成时，退出码为 1，
  标准错误输出 `Invalid draft`；即使目标版本不存在，也优先返回这一结果。
- 输入有效但数据库文件不存在，或库内没有对应版本时，退出码为 1，标准
  错误输出 `Version not found: <版本名>`；不会创建数据库文件或补建草稿。

### 追加变更

```
python release_notes.py --db notes.sqlite add-change <版本名> --change <变更>
```

- 每次调用只允许一个 `--change`，向指定草稿追加**一条**变更：新条目位于
  所有旧条目之后；重复文本分别保留，不去重。
- 版本名、追加文本原样保存：中文、标点、首尾空格及文本内部换行都保留，
  不自动裁剪或转义。多行文本仍只算一条变更，展示时只在首行前加 `- `，
  内部换行原样输出。版本名按原文精确匹配，区分大小写。
- 只改变更列表：标题、版本名以及旧条目的原文、数量、相对顺序均保持不变，
  其他版本不受影响。
- 成功时退出码为 0，标准输出为 `Added change: <版本名>` 加末尾换行，
  标准错误为空。
- 未提供或重复提供 `--change`，或版本名、追加文本为空 / 仅由空白组成时，
  退出码为 1，标准错误输出 `Invalid draft`；即使目标版本不存在也优先
  返回这一结果。
- 输入有效但数据库文件不存在，或库内没有对应版本时，退出码为 1，标准
  错误输出 `Version not found: <版本名>`；不会创建数据库文件或补建草稿。

### 替换单条变更

```
python release_notes.py --db notes.sqlite set-change <版本名> --index <序号> --change <新文本>
```

- 每次调用只允许一个 `--index` 和一个 `--change`，按当前展示顺序替换
  指定草稿的**一条**变更：条目数量、排列、版本名、标题以及其他版本均不
  改变；相同内容的重复条目仍分别保留。
- 序号从 1 开始、按记录而非输出行数计数，多行条目只占一个序号；只接受
  数字 0 至 9 组成且数值大于 0 的字符串，前导零不影响定位，输出与错误
  消息中的序号不保留前导零。
- 版本名、新文本原样保存：中文、标点、首尾空格及文本内部换行都保留，
  不自动裁剪或转义。版本名按原文精确匹配，区分大小写。
- 成功时退出码为 0，标准错误为空，标准输出为
  `Updated change: <版本名> #<序号>` 加末尾换行；提交与原文相同的文本
  也按成功处理，不改变任何内容。
- 未提供或重复提供 `--index`、`--change`，版本名或新文本为空 / 仅由
  空白组成，或序号不符合要求时，退出码为 1，标准错误输出
  `Invalid draft`；即使目标版本不存在也优先返回这一结果。
- 输入有效但数据库文件不存在，或库内没有对应版本时，退出码为 1，标准
  错误输出 `Version not found: <版本名>`。
- 版本存在但序号超过该草稿的条目数量时，退出码为 1，标准错误输出
  `Change not found: <版本名> #<序号>`。
- 以上失败的标准输出均为空，错误消息末尾带换行；不会创建数据库或草稿，
  也不改变已有内容。

### 删除单条变更

```
python release_notes.py --db notes.sqlite remove-change <版本名> --index <序号>
```

- 每次调用只允许一个 `--index`，按当前展示顺序删除指定草稿的**一条**
  变更：其余条目的原文与相对顺序不变，相同文本的其他记录仍保留，版本名、
  标题以及其他版本均不受影响。
- 序号从 1 开始、按记录而非输出行数计数，多行条目只占一个序号；只接受
  数字 0 至 9 组成且数值大于 0 的字符串，前导零不影响定位，输出与错误
  消息中的序号不保留前导零。
- 版本名按原文精确匹配，区分大小写。删除后序号按剩余记录重新计算：
  `set-change` 按新序号定位，`add-change` 仍追加到末尾。
- 成功时退出码为 0，标准错误为空，标准输出为
  `Removed change: <版本名> #<序号>` 加末尾换行。
- 未提供或重复提供 `--index`，版本名为空 / 仅由空白组成，或序号不符合
  要求时，退出码为 1，标准错误输出 `Invalid draft`；即使目标版本不存在
  也优先返回这一结果。
- 输入有效但数据库文件不存在，或库内没有对应版本时，退出码为 1，标准
  错误输出 `Version not found: <版本名>`。
- 版本存在但序号超过该草稿的条目数量时，退出码为 1，标准错误输出
  `Change not found: <版本名> #<序号>`。
- 草稿只剩一条变更且请求删除这一条时，退出码为 1，标准错误输出
  `Cannot remove last change: <版本名>`，该记录原样保留。
- 以上失败的标准输出均为空，错误消息末尾带换行；不会创建数据库或草稿，
  也不改变已有内容。

### 移动单条变更

```
python release_notes.py --db notes.sqlite move-change <版本名> --from <来源序号> --to <目标序号>
```

- 每次调用只允许一个 `--from` 和一个 `--to`，按当前展示顺序把指定草稿
  的**一条**变更从来源序号移动到目标序号：移动后所选条目恰好位于目标
  序号，其余条目的相对顺序不变；目标表示最终位置，不因来源在前而减一。
  来源与目标相同也按成功处理，内容与顺序保持不变。
- 两个序号都从 1 开始、按记录而非输出行数计数，多行条目只占一个序号；
  只接受数字 0 至 9 组成且数值大于 0 的字符串，前导零不影响定位，输出
  与错误消息中的序号不保留前导零。
- 只改所选版本的排列：条目数量、每条变更的原文（含首尾空格与内部换行）、
  重复记录、版本名、标题以及其他版本均保持不变。移动后 `set-change`、
  `remove-change` 按新序号定位，`add-change` 仍追加到末尾。
- 版本名按原文精确匹配，区分大小写。成功时退出码为 0，标准错误为空，
  标准输出为 `Moved change: <版本名> #<来源序号> -> #<目标序号>` 加末尾
  换行，序号均不保留前导零。
- 未提供或重复提供 `--from`、`--to`，版本名为空 / 仅由空白组成，或任一
  序号不符合要求时，退出码为 1，标准错误输出 `Invalid draft`；即使目标
  版本不存在也优先返回这一结果。
- 输入有效但数据库文件不存在，或库内没有对应版本时，退出码为 1，标准
  错误输出 `Version not found: <版本名>`。
- 版本存在后先检查来源再检查目标：序号超过该草稿的条目数量时，退出码
  为 1，标准错误输出 `Change not found: <版本名> #<序号>`；两个序号都
  越界时报告来源序号。
- 以上失败的标准输出均为空，错误消息末尾带换行；不会创建数据库或草稿，
  也不改变已有内容。

### 复制草稿

```
python release_notes.py --db notes.sqlite copy-version <原版本名> --to <新版本名>
```

- 每次调用在同一库内复制一份草稿：原版本保留不动，副本以新名称保存，
  可以在副本上继续整理。副本的标题、条目数量与展示顺序与原草稿当前
  内容一致；已经删除或移动过条目的草稿，以复制时的当前展示顺序为准。
- 变更原文逐条复制为独立记录：重复文本分别保留，多行文本仍是一条
  记录，副本条目的 position 从 0 连续编号（不复制原草稿可能存在的
  position 空洞）。
- 新名称、标题与变更中的中文、标点、首尾空格及内部换行均原样保留，
  不自动裁剪或转义。版本名按原文精确匹配，区分大小写。
- 复制完成后两份草稿互不影响：对任一份执行 `set-title`、`set-change`
  等修改，只改变该草稿，另一份的标题、条目与顺序保持不变。新草稿可
  通过 `show`、`list-drafts`（含 `--prefix`）、`export-markdown` 与
  `export-changelog` 读取，沿用原有排序、前缀筛选和输出格式。
- 成功时退出码为 0，标准错误为空，标准输出恰为
  `Copied version: <原版本名> -> <新版本名>` 加末尾换行。
- 原版本名或新版本名为空 / 仅由空白组成，或未提供 `--to`、显式给出
  却缺值、重复提供 `--to` 时，退出码为 1，标准输出为空，标准错误仅
  输出 `Invalid draft` 和一个换行；该校验先于数据库访问，即使数据库
  文件不存在也优先返回此错误，且不创建数据库。
- 输入有效后先确认原草稿：数据库文件不存在、库中没有 drafts 表（完全
  空库或只有无关表），或查无原版本（含仅大小写不同）时，退出码为 1，
  标准错误输出 `Version not found: <原版本名>`。
- 原草稿存在但新名称已被占用（原名与新名完全相同也属于此情况）时，
  退出码为 1，标准错误输出 `Version already exists: <新版本名>`。
- 以上失败的标准输出均为空，错误消息末尾带换行；不会创建数据库或
  补建表，不留下新草稿或部分条目，也不改变已有数据。

## 离线复现示例

以下示例不依赖网络，可直接复制到终端执行。

创建草稿：

```sh
python release_notes.py --db notes.sqlite create 0.1.0 \
  --title "首个预览版" \
  --change "新增草稿创建" \
  --change "支持版本查看"
```

输出（退出码 0）：

```
Created 0.1.0
```

查看草稿（也可以结束当前进程后，在新的进程中用同一数据库路径执行）：

```sh
python release_notes.py --db notes.sqlite show 0.1.0
```

输出（退出码 0）：

```
Version: 0.1.0
Title: 首个预览版
- 新增草稿创建
- 支持版本查看
```

只修订标题（版本名与变更保持不变）：

```sh
python release_notes.py --db notes.sqlite set-title 0.1.0 --title "首个预览修订"
```

输出（退出码 0）：

```
Updated title: 0.1.0
```

再次查看，标题已更新，其余内容与之前完全一致：

```sh
python release_notes.py --db notes.sqlite show 0.1.0
```

输出（退出码 0）：

```
Version: 0.1.0
Title: 首个预览修订
- 新增草稿创建
- 支持版本查看
```

向已有草稿追加一条变更（标题与旧条目保持不变）：

```sh
python release_notes.py --db notes.sqlite add-change 0.1.0 --change "修正提示文案"
```

输出（退出码 0）：

```
Added change: 0.1.0
```

再次查看，新条目排在所有旧条目之后：

```sh
python release_notes.py --db notes.sqlite show 0.1.0
```

输出（退出码 0）：

```
Version: 0.1.0
Title: 首个预览修订
- 新增草稿创建
- 支持版本查看
- 修正提示文案
```

按展示顺序替换单条变更（标题、其他条目与顺序保持不变）：

```sh
python release_notes.py --db notes.sqlite set-change 0.1.0 --index 2 --change "支持版本查看与修订"
```

输出（退出码 0；序号前导零不影响定位，输出不保留前导零）：

```
Updated change: 0.1.0 #2
```

再次查看，只有第二条变更被替换，条目数量与顺序不变：

```sh
python release_notes.py --db notes.sqlite show 0.1.0
```

输出（退出码 0）：

```
Version: 0.1.0
Title: 首个预览修订
- 新增草稿创建
- 支持版本查看与修订
- 修正提示文案
```

序号超过条目数量时失败，已有内容保持不变：

```sh
python release_notes.py --db notes.sqlite set-change 0.1.0 --index 4 --change "不应写入"
# 退出码 1，标准错误：Change not found: 0.1.0 #4
```

再次创建同名版本会失败，原有内容保持不变：

```sh
python release_notes.py --db notes.sqlite create 0.1.0 \
  --title "重复版本" --change "不应写入"
# 退出码 1，标准错误：Version already exists: 0.1.0
```

传入空白变更同样失败：

```sh
python release_notes.py --db notes.sqlite create 0.2.0 \
  --title "空白变更" --change "   "
# 退出码 1，标准错误：Invalid draft
```

失败后再次查看 `0.1.0`，仍得到与首次创建完全一致、顺序不变的内容。

把单个草稿按固定 Markdown 格式导出到标准输出（只读，不产生文件；需要
保存时由终端重定向）：

```sh
python release_notes.py --db notes.sqlite export-markdown 0.1.0
```

输出（退出码 0，标准错误为空）：

```
# 0.1.0

首个预览修订

- 新增草稿创建
- 支持版本查看与修订
- 修正提示文案
```

版本名为空时优先报 `Invalid draft`，即使数据库文件尚不存在也是如此：

```sh
python release_notes.py --db not-yet.sqlite export-markdown "   "
# 退出码 1，标准错误：Invalid draft
# not-yet.sqlite 不会被创建
```

把目录中的多份草稿按版本名 Unicode 码点顺序汇总成一份 Markdown
（只读，不产生文件；需要保存时由终端重定向）：

```sh
python release_notes.py --db notes.sqlite export-changelog
```

接上例，若库中还有 `0.2.0`，则先完整输出 `0.1.0` 的片段，再输出
`0.2.0` 的片段，两份片段之间多一个换行；加 `--prefix 0.2` 时只输出
`0.2.0` 的片段，与单份导出逐字相同。显式给出非法 `--prefix`（缺值、
空白或重复提供）时先报 `Invalid draft`，即使数据库文件不存在也是如此；
没有匹配项或数据库不存在时退出码为 0 且两个输出流都为空。

保留原版本并复制一份草稿，以新名称继续整理：

```sh
python release_notes.py --db notes.sqlite copy-version 0.1.0 --to 0.1.1
```

输出（退出码 0，标准错误为空）：

```
Copied version: 0.1.0 -> 0.1.1
```

新进程查看 `0.1.1`，版本名为新名称，标题与条目按原顺序逐字一致；
`0.1.0` 仍然存在且内容不变：

```sh
python release_notes.py --db notes.sqlite show 0.1.1
```

输出（退出码 0）：

```
Version: 0.1.1
Title: 首个预览修订
- 新增草稿创建
- 支持版本查看与修订
- 修正提示文案
```

之后只修改副本（例如替换标题），原草稿不受影响：

```sh
python release_notes.py --db notes.sqlite set-title 0.1.1 --title "补丁预览"
# show 0.1.1 的标题为"补丁预览"；show 0.1.0 的标题仍是"首个预览修订"
```

新名称已被占用（包括与原名相同）时失败，不写入任何内容：

```sh
python release_notes.py --db notes.sqlite copy-version 0.1.0 --to 0.1.0
# 退出码 1，标准错误：Version already exists: 0.1.0
```

> 提示：`notes.sqlite` 等数据库文件已在 `.gitignore` 中忽略。需要重置
> 示例数据时，删除该文件后重新执行创建命令即可。
