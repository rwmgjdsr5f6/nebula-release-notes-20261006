1. 保存位置

   - 介质：--db 指定的单个 SQLite 文件，create 与 show 用同一路径
     （README.md:11-13）。验收示例中即命令行里的 notes.sqlite。
   - 建库建表时机：cmd_create 在校验通过之后才
     sqlite3.connect(args.db)（release_notes.py:57）并
     executescript(SCHEMA)（release_notes.py:59）；SCHEMA 中两条
     CREATE TABLE 均带 IF NOT EXISTS（release_notes.py:17、21），
     重复执行幂等。
   - 因为 Invalid draft 校验位于 connect 之前
     （release_notes.py:45-47 注释、:48-55 先于 :57），README.md:12-13
     “首次有效创建时若该文件不存在会自动建立数据库”中的“有效”二字
     与代码相符：无效输入不会产生文件。
   - show 不建库：先 os.path.exists(args.db)，文件不存在直接判为
     版本不存在（release_notes.py:91-93），随后才 connect（:95）；
     cmd_show 全程不执行任何建表语句（release_notes.py:90-119）。
   - 写入是一个事务：with conn（release_notes.py:61）包裹 drafts 插入
     （:68-71）与 changes 批量插入（:72-79），正常退出 with 块才提交；
     并发同主键冲突触发 sqlite3.IntegrityError 时由
     release_notes.py:80-82 捕获并回滚（该分支静态可见，并发时机未
     运行验证）。
   - 数据库文件被 .gitignore 第 6-8 行的 *.sqlite / *.sqlite3 /
     *.sqlite-* 模式忽略（README.md:104-105 亦有同样提示）。

2. 存储结构（SCHEMA：release_notes.py:16-28）

   drafts(version TEXT PRIMARY KEY, title TEXT NOT NULL)        :17-20
   changes(id INTEGER PRIMARY KEY AUTOINCREMENT,                :21-27
           version TEXT NOT NULL, position INTEGER NOT NULL,
           content TEXT NOT NULL,
           FOREIGN KEY (version) REFERENCES drafts(version))

3. 进程退出、重新打开存储后仍可取得的数据

   程序自身没有跨进程状态：每次调用都新建 sqlite3 连接
   （release_notes.py:57、95），并在 finally 中关闭
   （release_notes.py:83-84、112-113）。持久化全部落在 --db 文件里；
   README.md:71-75 明确可以结束进程后，在新进程中用同一数据库路径
   再次查看。

   重新打开后，经公开入口 show 可取得：
   - 版本名：drafts.version（主键，release_notes.py:18）；show 输出的
     Version 行回显查询参数（release_notes.py:116），按该主键定位
     （release_notes.py:98）。
   - 标题：drafts.title（release_notes.py:68-71 写入、:97-102 读回）。
   - 每条变更原文：changes.content（release_notes.py:72-79 写入、
     :104-111 读回）。
   - 条目顺序：changes.position（0 起，release_notes.py:77 写入、
     :108 ORDER BY 读回）。
   存储中另有 changes.id 自增值（release_notes.py:22、:72-79），但
   show 的 SELECT 只取 content（release_notes.py:107），现有公开入口
   无法读到 id；即“数据在文件中保留，但无公开入口可取”。

4.1 创建草稿

  python release_notes.py --db notes.sqlite create demo-0.1 \
    --title "离线示例" \
    --change "新增预览" \
    --change "调整提示"

按源码静态推演：
  (1) argparse 收集结果（release_notes.py:129-137、43）：
        args.version = "demo-0.1"
        args.title   = "离线示例"
        args.change  = ["新增预览", "调整提示"]   # append 顺序即传入顺序
  (2) 校验（release_notes.py:48-55）：版本名非空白；标题非 None 且
      非空白；变更列表非空；逐条非空白——四项均不命中，继续。
  (3) connect 并 executescript 建库建表（release_notes.py:57-59）；
      notes.sqlite 不存在则由此创建。
  (4) 查重 SELECT 1 FROM drafts WHERE version = ?（:62-64），新库无
      此行（:65 判断为 None），继续。
  (5) 同一事务内（release_notes.py:61）：
        INSERT drafts：("demo-0.1", "离线示例")            (:68-71)
        INSERT changes 两行（:72-79，position 取自 enumerate :77）：
          ("demo-0.1", 0, "新增预览")
          ("demo-0.1", 1, "调整提示")
      退出 with 块无异常，事务提交。
  (6) 输出并返回（release_notes.py:86-87）。

  预期结果（静态推演）：退出码 0；stderr 无输出；stdout 恰好一行：

      Created demo-0.1

  与 README.md:26 的约定一致。

4.2 第一次查看（可在同一进程结束后，于新进程执行；见 4.3）

按源码静态推演：

  (2) SELECT title ... fetchone 得到 ("离线示例",)，非 None
      （release_notes.py:97-101）；title = "离线示例"（:102）。
  (3) SELECT content ... ORDER BY position（release_notes.py:104-111）

  (4) 拼装（release_notes.py:116-118）：两行头 + 两条 "- " 行，以

4.3 重新打开本地存储后的第二次读取，以及如何核对三项内容

  操作方式：确认 4.1 的进程已经退出，重新执行与 4.2 完全相同的命令
  （新进程、同一 --db 路径）：

      python release_notes.py --db notes.sqlite show demo-0.1

  这条路径被 README.md:71-75 明确列为支持的用法。源码保证它不依赖
  任何内存状态：每次进程都重新 connect（release_notes.py:95）、
  查询后在 finally 关闭（:112-113）。

  预期输出与 4.2 逐字节相同（静态推演）：

      Version: demo-0.1
      Title: 离线示例
      - 新增预览
      - 调整提示

  核对方法（每一项都能指到存储与读取位置）：
  - 核对标题：第 2 行必须恰好是 "Title: 离线示例"。该值由 show 从
    drafts.title 读回（release_notes.py:97-102），该列在创建时由
    参数化 INSERT 原样写入（release_notes.py:68-71）；全链路没有
    strip 或转义（release_notes.py:42-87、115-118）。若标题被改动，
    只可能来自对同一数据库的其他写入，而本程序只提供 create/show
    两个子命令（release_notes.py:127-142），没有修改入口。
  - 核对文本原样：第 3、4 行去掉固定前缀 "- "（release_notes.py:117）
    后，必须分别恰好等于输入的 "新增预览" 与 "调整提示"，不得出现
    裁剪、转义或字符替换。依据：写入用 ? 绑定（:73-78）、读取取
    changes.content 原值（:104-111）、输出只加固定前缀（:116-117），
    且 stdout 固定 UTF-8（:149-150，对应 README.md:23-24 的原样
    承诺）。
  - 核对顺序：第 3 行必须是先输入的 "新增预览"，第 4 行必须是后输入
    的 "调整提示"。依据：创建时 enumerate 从 0 编号
    （release_notes.py:77，"新增预览"→position 0，
    "调整提示"→position 1），查看时 ORDER BY position 升序
    （release_notes.py:107-109），再按取回顺序生成输出行
    （release_notes.py:117）。顺序由数据库中的 position 决定，不依赖
    当前进程，因此第二次读取顺序不变。
  - 版本名核对：第 1 行 "Version: demo-0.1" 与命令行查询参数一致；
    行能被查到本身即说明 drafts 中 version="demo-0.1" 的主键行持久
    存在（release_notes.py:98、18）。
