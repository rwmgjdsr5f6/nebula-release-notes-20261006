三、前缀匹配与排序规则（源码依据）
--------------------------------------------------------------------------------

1. 前缀只匹配版本名，区分大小写、不裁剪空白
   筛选就是 Python 的 str.startswith（release_notes.py:214），作用于
   row[0]（版本名）；前缀原文在 validate_draft_prefix 的 199 行返回后
   不经 strip/lower/任何转换。标题与变更不参与匹配：SELECT 只取
   version、title 两列（212 行），筛选只用 row[0]，title（row[1]）仅
   用于 list-drafts 的输出，在 export-changelog 中于 297 行解包为
   _title 后被丢弃，片段标题改由 read_draft_on_conn 重新按版本名读取
   （298-303 行）。约定：README.md:141-143。

2. % 与 _ 是普通字符
   全程没有 SQL LIKE：212 行是无 WHERE 的 SELECT，214 行在 Python 侧
   匹配，'%'(U+0025) 与 '_'(U+005F) 只匹配各自的字面字符
   （README.md:142-143；help 文本 release_notes.py:799-801）。

3. 省略 --prefix 时汇总全部草稿
   参数无 default（release_notes.py:794-802），省略时 args.prefix 为
   None，validate_draft_prefix 走 195-196 行返回 (None, True)，
   select_draft_rows 的 213-214 行筛选整段跳过，全部草稿进入排序与
   导出。约定：README.md:139-140。

4. 版本按 Unicode 码点顺序排列
   215 行 rows.sort(key=lambda row: row[0]) 是 Python 字符串比较：按
   Unicode 码点逐字符升序，前缀相同时较短名称在前，不合并大小写不同
   的名称，不解析语义版本。条目按当前展示顺序输出（ORDER BY position，
   147-150 行），重复文本分别保留（不去重），多行变更仍是一条记录。
   约定：README.md:144-147、152-153。

四、片段生成与输出格式（源码依据）
--------------------------------------------------------------------------------

1. 单个片段与 export-markdown 输出逐字一致
   两处共用 render_draft_markdown（release_notes.py:245-257）：
   export-markdown 在 273 行直接写出该函数结果；export-changelog 在
   304-306 行把同一函数结果收入 fragments。源码 docstring（251-253 行）
   明示“不允许各写一份拼接逻辑”。约定：README.md:149-150。

2. 片段间额外插入一个换行，末份之后不追加内容
   317 行 "\n".join(fragments)：每份片段已以最后一条变更自带的一个
   换行结尾（256-257 行），join 在相邻片段间再插入恰好一个换行，呈现
   为一个空行间隔；join 不在末尾追加任何内容，故最后一份片段的结尾
   换行就是整个输出的最后一个字节。约定：README.md:150-151。

3. 原文保持不变
   版本名、标题、变更从数据库取出后只做固定格式拼接：不去重、不裁剪
   空白、不转义，原文中的首尾空格和内部换行保持不变；多行变更只在
   首行前加 "- "，内部换行原样保留（render_draft_markdown 245-257 行；
   read_draft_on_conn 144-151 行）。约定：README.md:151-153。

五、失败优先级：非法 --prefix 先于一切数据库访问
--------------------------------------------------------------------------------

非法取值（validate_draft_prefix 197-198 行逐一覆盖）：
  - 显式缺值：--prefix 位于末尾且不带值（nargs="?" + const=""，
    release_notes.py:796-797，空串进入处理函数）；
  - 显式空字符串：--prefix ""（is_blank 的 == 分支，45 行）；
  - 仅含空白：--prefix "   "、" \t\n "（str.isspace() 分支，45 行，
    制表/换行也算空白）；
  - 重复提供：--prefix v1 --prefix v1、--prefix v1 --prefix v2
    （action="append" 使 len(prefixes)==2，197 行 len != 1 即拒，
    与两个值是否合法无关）。

静态推演路径：
  281 行校验失败 → 283 行 return fail("Invalid draft")；fail
  （49-52 行）向 stderr 打印消息并由 print 补一个换行，返回 1，经
  938-939、942-943 行成为进程退出码。此路径上没有任何 stdout 写入，
  317 行不可达 → 标准输出为空。数据库访问全部在校验之后
  （open_drafts_readonly 在 288 行），不可达 → 即使 --db 指向的路径
  不存在，也不会创建数据库文件，目录下不产生任何其他文件。
  约定：README.md:156-159（校验优先于数据库读取，即使数据库文件不
  存在也优先返回此错误且不创建任何文件）。

静态推演预期（逐字节）：
  退出码：1
  标准输出：空
  标准错误：恰为 "Invalid draft" 加一个换行（\n），除此之外无任何内容

实际观察（/tmp/ec_demo，数据库 missing.sqlite 不存在）：
  python release_notes.py --db missing.sqlite export-changelog --prefix
  → 退出码 1；stdout 0 字节；stderr 经 od -c 核对恰为
    I n v a l i d   d r a f t \n（13 字节）；missing.sqlite 未被创建。
  另实测 --prefix "  "（仅空白）与 --prefix v1 --prefix v2（重复提供）
  在数据库存在时同样：退出码 1，stdout 0 字节，stderr 恰为上述 13 字节。
  与静态推演一致。

六、四种“有效输入但无输出”：退出码 0，两个输出流均为空
--------------------------------------------------------------------------------

前提都是参数先通过了 281-283 行校验；非法前缀不享受空结果待遇（见
第五节）。四种已约定情形（README.md:160-162）：

  情形                          源码路径（release_notes.py）        副作用
  ----------------------------  ----------------------------------  --------
  1. 合法前缀无匹配              212 取数；213-214 筛选后 rows 为空；  无
                                296-306 循环不执行；311-312 返回 0
  2. --db 指向的文件不存在       112-113 返回 None；289-290 返回 0    不建库
  3. 文件存在但没有 drafts 表    119-122 查 sqlite_master 得 None；    不补表
    （完全空库或只有无关表）     123-125 关闭并返回 None；289-290
  4. drafts 表存在但表内无草稿   212 SELECT 取回空列表；311-312        不写行

输出契约：四种情形统一退出码 0，标准输出与标准错误都为空——连换行都
不输出（310-312 行在写出之前返回，317 行不可达；成功路径不写 stderr）。

“不建库、不补表”的源码依据：
  - SCHEMA（release_notes.py:29-41）在整个 export-changelog 路径上从未
    被执行；它只在 cmd_create 的 72 行经 executescript 建立。
  - open_drafts_readonly（103-126 行）对库结构的全部探测只是只读的
    sqlite_master 查询（119-122 行），docstring 118 行附近明示“不会
    开启写事务或产生 journal”；文件不存在时连 sqlite3.connect 都不
    发生（112 行门控 115 行）。

实际观察（/tmp/ec_demo）：
  - --prefix v9（库存在、无匹配）：退出码 0，stdout 0 字节，stderr 0 字节；
  - --db absent.sqlite（不存在）：退出码 0，两流均 0 字节，absent.sqlite
    未被创建；
  - 空 drafts 表（有表无行）：退出码 0，两流均 0 字节；
  - 只有无关表、无 drafts 表：退出码 0，两流均 0 字节，未补建表。
  与静态推演一致。

七、只读性与跨进程结果稳定（不建库、不补表、不生成文件、不改数据）
--------------------------------------------------------------------------------

1. 不建库、不补表、不生成导出文件、不改变已有数据（源码依据）
   cmd_export_changelog 函数体（release_notes.py:277-318）及其调用的
   open_drafts_readonly（103-126）、select_draft_rows（202-216）、
   read_draft_on_conn（129-152）中只有 SELECT 语句（sqlite_master、
   drafts、changes 各一条），没有 CREATE/INSERT/UPDATE/DELETE，没有
   executescript(SCHEMA)，也没有 with conn 事务或 commit。唯一的输出
   是 317 行的 sys.stdout.write：命令不接收输出路径，不创建任何发布
   说明文件，需要保存时由终端重定向。已有草稿的名称、标题、条目数量
   与顺序保持不变。约定：README.md:163-166；模块 docstring
   release_notes.py:18-19。

2. 数据未变化时，新进程得到相同文本
   每次进程都从 main 重新解析参数、重新连接（release_notes.py:933-939），
   输出只由 drafts/changes 当前内容决定：筛选（214 行）、排序（215 行）
   与拼接（255-257、317 行）都是确定性的纯函数。212 行的 SELECT 本身
   没有 ORDER BY，物理返回顺序不具契约意义；215 行的 Python 排序使
   最终顺序对同一数据恒定，因此不同进程、重复执行得到逐字节相同的
   stdout（README.md:165-166：“另一个进程使用同一路径汇总得到完全
   一致的文本”）。

八、可复核示例：两份虚构草稿的两次导出
--------------------------------------------------------------------------------

数据准备（创建流程：cmd_create，release_notes.py:55-100；非空白校验
61-68 行；建库建表 70-72 行；写 drafts 与 changes 在同一事务 74-92 行）。
严格按以下顺序创建——先 v2，后 v10：

  python release_notes.py --db notes.sqlite create v2 \
    --title "含 v1 的标题" --change "修正文案"
  # 退出码 0，stdout：Created v2

  python release_notes.py --db notes.sqlite create v10 \
    --title "预览十" --change "新增查询" --change "新增查询"
  # 退出码 0，stdout：Created v10

于是数据库中：
  drafts：  (v2, 含 v1 的标题)、(v10, 预览十)
  changes： v2 一条（position 0，修正文案）；
            v10 两条（position 0 与 1，内容均为“新增查询”——重复文本
            分别保存为独立记录，create 不去重，release_notes.py:85-92）。
注意 v2 的标题“含 v1 的标题”中含有子串“v1”，用于验证标题不参与
前缀筛选。

第一次导出（省略 --prefix，汇总全部草稿）：

  输入：
    python release_notes.py --db notes.sqlite export-changelog

  静态推演（沿第二节路径）：
    A. args.prefix 为 None → 195-196 行，不筛选；
    B. notes.sqlite 存在且有 drafts 表 → 288 行连接成功；
    C. 212 行取回 (v2, …)、(v10, …) 两行；213-214 行跳过；
       215 行按码点排序：'v'='v'，'1'(U+0031) < '2'(U+0032)，
       故 v10 排在 v2 之前——与创建顺序（先 v2 后 v10）相反，
       也与语义版本直觉（2 < 10）相反，证明只按码点；
    D-E. 逐份读取并渲染：v10 片段含两条相同的“- 新增查询”
