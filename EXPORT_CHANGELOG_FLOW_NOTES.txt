--------------------------------------------------------------------------------

1. export-changelog 是只读汇总：处理函数 cmd_export_changelog
   （release_notes.py:277-318）路径上只有 SELECT，不执行 SCHEMA、不建库、
   不补表、不写数据、不接收输出路径、不生成文件，文本只经
   sys.stdout.write 写到标准输出（release_notes.py:317）。
2. --prefix 校验先于一切数据库访问（release_notes.py:281-283 先于 288）。
   缺值、空串、纯空白、重复提供一律退出 1，stdout 空，stderr 恰为
   "Invalid draft\n"；即使数据库文件不存在也如此。
3. 参数有效时，数据库文件不存在 / 无 drafts 表 / 表空 / 前缀无匹配：
   统一退出 0 且 stdout、stderr 均为空（连换行都没有）
   （release_notes.py:289-290、311-312）。
4. 前缀只在 Python 侧按版本名原文 str.startswith 匹配：区分大小写、不裁剪
   空白、% 与 _ 是普通字符，标题与变更不参与匹配
   （release_notes.py:212-214）。省略 --prefix 时 prefix 为 None，汇总全部
   草稿（release_notes.py:195-196、213）。
5. 草稿按版本名原文在 Python 侧排序，即 Unicode 码点升序
   （release_notes.py:215）；每份草稿的变更按 position 升序的当前展示顺序
   读取，不去重、不裁剪，多行变更仍是一条记录
   （release_notes.py:144-151）。
6. 每份片段由 render_draft_markdown 逐字拼接
   （release_notes.py:245-257），export-markdown 也调用同一函数
   （release_notes.py:273），故单份片段与 export-markdown 成功输出逐字一致；
   片段间用 "\n".join 额外插入恰好一个换行，末份之后不追加任何内容
   （release_notes.py:317）。

三、匹配与排序语义的源码核对（静态推演）
--------------------------------------------------------------------------------

1. 只匹配版本名；区分大小写；不裁剪空白
   匹配即 row[0].startswith(prefix)（release_notes.py:214）：前缀原文在
   198 行返回后不经 strip/lower；SQL 本身无 WHERE（212 行）。
   - 标题在 SELECT 中取回（212 行 row[1]）但只用于渲染，筛选处从不引用；
     变更表在本函数中完全不查询（changes 由步骤 D 按选中版本另行读取）。
   - 'V'(U+0056) 与 'v'(U+0076) 不同码点，"V1" 不命中前缀 "v1"。
   - 合法前缀中可含空格/制表/内部换行：is_blank（44-46 行）只拒绝“整个值
     为空或全部为空白”，不拒绝含空白字符的非空白值；空格 U+0020、换行
     U+000A 作为真实码点逐字符参与 startswith。
   约定：README.md:140-143。

2. % 与 _ 是普通字符
   因为没有使用 SQL LIKE——212 行是无 WHERE 的 SELECT，214 行在 Python 侧
   匹配，'%'(U+0025) 与 '_'(U+005F) 只匹配各自的字面字符，没有“任意串 /
   任意单字符”的通配含义（help 文本 release_notes.py:800-801；
   README.md:142-143）。

3. 省略 --prefix 汇总全部
   参数无 default，省略时 args.prefix is None；validate_draft_prefix 在
   195-196 行返回 (None, True)；select_draft_rows 在 213 行
   `if prefix is not None` 处跳过筛选，仅保留 215 行排序。
   README.md:139-140。

4. 版本按 Unicode 码点顺序，不按创建顺序、不按语义版本
   排序只有 rows.sort(key=lambda row: row[0])（release_notes.py:215）：
   Python 字符串按 Unicode 码点逐字符比较。因此 "v10" < "v2"
   （第二码点 '1' U+0031 < '2' U+0032），与语义版本序 10 > 2 恰好相反；
   物理存储顺序（212 行 SELECT 无 ORDER BY）不具契约意义，215 行的 Python
   排序使输出对同一数据恒定。README.md:144-146。

5. 条目按当前展示顺序；重复文本分别保留；多行变更仍是一条记录
   变更只经 ORDER BY position 读取（release_notes.py:147-148），读取与渲染
   都没有去重（214 行筛选不看内容；256 行逐条 extend）。重复文本是 changes
   表中各自独立的行（create 多 --change 与 add-change 都逐行插入：
   release_notes.py:85-92、432-436），渲染时各自产生一行 "- ..."。
   多行内容中的内部换行不经任何处理（256 行 f-string 原样拼接），只占一条
   记录、一个 "- " 前缀。README.md:146-147、151-153。

6. 空格与换行保持不变
   全程无 strip / 规范化 / 转义：读取是 SELECT 原文（138-151 行），渲染是
   原样 f-string（255-256 行），输出编码固定 UTF-8（935-936 行）。
   README.md:151-153。

四、两份虚构草稿的可复核示例
--------------------------------------------------------------------------------

以下数据为虚构，且刻意构造两个“陷阱”：
  - 先创建 v2、后创建 v10，但码点序要求 v10 排在 v2 之前（证排序）；
  - v2 的标题“含 v1 的标题”中含有子串 v1，但 --prefix v1 不得选中 v2
    （证标题不参与匹配）；
  - v10 保存两条逐字相同的“新增查询”（证重复文本分别保留）。

【实际观察】下列命令已于 2026-10-08 在 /tmp 临时目录用 Python 3.14.4 执行；
若需自行复核，可在任意空目录按序执行（*.sqlite 已被 .gitignore 忽略）。

准备数据（三条命令，均退出 0）：

  python release_notes.py --db notes.sqlite create v2 \
      --title "含 v1 的标题" --change "修正文案"
    stdout: Created v2\n        stderr: 空
  python release_notes.py --db notes.sqlite create v10 \
      --title "预览十" --change "新增查询"
    stdout: Created v10\n       stderr: 空
  python release_notes.py --db notes.sqlite add-change v10 \
      --change "新增查询"
    stdout: Added change: v10\n stderr: 空

数据来源的源码依据：create 的非空白校验先于连接数据库
（release_notes.py:61-68），建库建表在 70-72 行，drafts/changes 同一事务
插入（81-92 行）；add-change 每次只插一条独立记录、新 position 为
MAX(position)+1（release_notes.py:423-436），故第二条“新增查询”是 position=1
的独立行，不去重。入库后表内状态（【实际观察】，list-drafts 印证）：

  drafts: (v10, 预览十)、(v2, 含 v1 的标题)
  changes: v10 → position 0 "新增查询"；position 1 "新增查询"
           v2  → position 0 "修正文案"

示例 1：省略 --prefix，汇总全部草稿
--------------------------------

输入：

  python release_notes.py --db notes.sqlite export-changelog

静态推演（沿第二节步骤 A-F）：
  A args.prefix is None → prefix=None，校验通过（195-196、281-283 行）；
  B 文件存在且有 drafts 表 → 拿到连接（112、119-125 行）；
  C 212 行取回两行；prefix is None，213 行跳过筛选；215 行按码点排序：
    "v10" 与 "v2" 第二码点 '1'(U+0031) < '2'(U+0032) → 顺序 v10、v2
    （与创建顺序 v2、v10 相反）；
  D 分别经 138-151 行读取：v10 得标题“预览十”与两条“新增查询”
    （两条 position 0、1 独立成行，文本相同也各自保留）；v2 得标题
    “含 v1 的标题”与一条“修正文案”；
  E 255-257 行各拼一个片段；
  F fragments 非空，317 行 "\n".join 输出：v10 片段以第二条变更的 "\n"
    结尾，join 在它与 "# v2" 之间再插一个 "\n"（共呈一个空行），末份之后
    不追加。

预期标准输出（可视化块；退出码 0，标准错误为空）：

# v10

预览十

- 新增查询
- 新增查询

# v2

含 v1 的标题

- 修正文案

同一内容逐字节表示（\n 显式标注换行，引号内为 stdout 全部字节，末尾无
