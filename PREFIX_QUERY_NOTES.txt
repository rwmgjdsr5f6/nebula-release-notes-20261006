以下按执行顺序列出每个分支，均可沿行号核对。

第 1 步：参数校验（先于任何数据库访问）
  release_notes.py:153-159：

    if prefixes is not None:
        if len(prefixes) != 1 or is_blank(prefixes[0]):

        prefix = None
  - 省略 --prefix：prefixes 为 None（release_notes.py:154），prefix 置
    None，表示不筛选、保留全部目录行为（release_notes.py:158-159）。
  - 重复提供：len(prefixes) != 1（release_notes.py:155），无效。
  - 显式缺值：nargs='?' 落空取 const=""（release_notes.py:592-593），
    空串经 is_blank 判为空白（release_notes.py:42-44：空字符串或仅由
    空白字符组成，含换行），无效。
  - 值为空或仅含空白：同样由 is_blank 判为无效。
  - 失败出口：fail（release_notes.py:47-50）向标准错误打印消息并返回 1；

    release_notes.py:149-152）。对应 README.md:90-92。

第 2 步：数据库文件存在性检查（不建库）

  - 文件不存在：不连接、不建库，items 保持空列表，直接落到第 5 步输出
    []（注释见 release_notes.py:161）。对应 README.md:70-71。

第 3 步：草稿表存在性检查（不补建表）

  - 读取：release_notes.py:173-175，

    只取版本名与标题两列，不读取变更条目（对应 README.md:63-64 的

  - 组装：release_notes.py:188-191，每行变为

三、只读性质与跨进程一致性
--------------------------------------------------------------------------------

- 不补建表：cmd_list_drafts 全程不执行 SCHEMA（对比 cmd_create 在
  release_notes.py:70 的 executescript）；第 3 步只查询 sqlite_master。
- 不建库：数据库文件不存在时在第 2 步即短路，从不调用
  sqlite3.connect（release_notes.py:163-164），missing.sqlite 一类
  路径不会被创建。
- 不改数据：函数内只有 SELECT（release_notes.py:168-175），没有任何
  INSERT/UPDATE/DELETE，草稿与变更的原文、条目数量与展示顺序均不受
  查询影响；也不创建其他文件。
- 跨进程一致：以上只读性质意味着数据未变化时，另一个进程使用同一路径
  查询得到相同数组。对应 README.md:72-74。

四、固定样例（静态推演，预期结果已按第一节方法核对）
--------------------------------------------------------------------------------

样例数据（本次说明固定使用）：按如下创建顺序依次建四份草稿，每份只有
一条内容为“示例”的变更：

  python release_notes.py --db notes.sqlite create v10   --title 后续   --change 示例
  python release_notes.py --db notes.sqlite create other --title v1     --change 示例
  python release_notes.py --db notes.sqlite create V1    --title 大小写 --change 示例
  python release_notes.py --db notes.sqlite create v1    --title 预览   --change 示例

即：
  创建顺序  版本名  标题    变更
  1         v10     后续    示例
  2         other   v1      示例
  3         V1      大小写  示例
  4         v1      预览    示例

4.1 带前缀查询（本文核心样例）

  python release_notes.py --db notes.sqlite list-drafts --prefix v1

预期结果（按第二节路径静态推演）：
  退出码：0
  标准错误：空
  标准输出：恰为下面一行，后接一个换行，无其他内容：
  [{"version": "v1", "title": "预览"}, {"version": "v10", "title": "后续"}]

推演过程：
  - 校验：prefixes == ["v1"]，长度为 1 且非空白，通过
    （release_notes.py:154-157）。
  - 读取：四行 (version, title) 全部取出（release_notes.py:173-175）。
  - 筛选："v1".startswith 判定（release_notes.py:181-183）：
      v10  → 以 "v1" 开头，保留；
      v1   → 以 "v1" 开头，保留；
      other→ 不以 "v1" 开头，排除。注意 other 的标题恰为 "v1"，但标题
             不参与匹配（release_notes.py:177-180 注释，README.md:83）；
      V1   → 排除。startswith 区分大小写：'V' 的码点 U+0056 与 'v' 的
             U+0076 不同，首字符即不等（README.md:85）。
  - 排序：剩下 "v1" 与 "v10"，按 Unicode 码点逐字符比较，"v1" 是 "v10"
    的前缀且较短，故 "v1" 在前（release_notes.py:187，README.md:68-69）。
    结果取决于版本名原文的码点顺序，而非创建顺序（v10 先创建却排在后）
    或语义版本大小（不做任何版本号解析）。
  - 输出：json.dumps(..., ensure_ascii=False) 使“预览”“后续”直接以
    UTF-8 输出，元素间分隔为 ", "，键后冒号带空格，末尾恰一个换行
    （release_notes.py:197）。该输出经 JSON 解析后，版本名与标题与
    保存原文完全一致（README.md:65-67）。

4.2 省略前缀（对照）

  python release_notes.py --db notes.sqlite list-drafts

预期结果：退出码 0，标准错误为空，标准输出为全部四份草稿、后接一个
换行（prefix 为 None，不筛选，release_notes.py:154、158-159、176）：
  [{"version": "V1", "title": "大小写"}, {"version": "other", "title": "v1"}, {"version": "v1", "title": "预览"}, {"version": "v10", "title": "后续"}]
排序依据码点：'V'(U+0056) < 'o'(U+006F) < 'v'(U+0076)，与创建顺序
无关。

4.3 前缀文本的边界性质（沿源码可核对）

  - % 与 _ 是普通字符：筛选用 str.startswith 而非 SQL LIKE
    （release_notes.py:177-183），--prefix "v%" 只匹配字面以 "v%"
    开头的版本名，本样例中无匹配，预期输出 [] 加换行。
  - 首尾空格与内部换行按原文比较：is_blank 只拒绝“整个值皆为空白”
    （release_notes.py:42-44）；像 " v1" 这样含首尾空格但非全空白的
    前缀会原样进入 startswith，本样例中无匹配，预期输出 [] 加换行。
  - 返回文本保真：版本名与标题经 JSON 解析后与保存原文一致，首尾空格
    与内部换行均不裁剪（release_notes.py:195-197，README.md:65-67）。

五、失败优先级与空结果分支（静态推演，预期结果已核对）
--------------------------------------------------------------------------------

5.1 失败优先级演示命令

  python release_notes.py --db missing.sqlite list-drafts --prefix

  （--prefix 后不给值；执行前 missing.sqlite 不存在）

预期结果：
  退出码：1
  标准输出：空
  标准错误：恰为下面一行（Invalid draft 加一个换行）：
  Invalid draft
  副作用：missing.sqlite 不被创建。

推演过程：--prefix 缺值时 nargs='?' 落空取 const=""，prefixes == [""]
（release_notes.py:589-597）；is_blank("") 为真（release_notes.py:42-44），
在 release_notes.py:155-156 直接 return fail("Invalid draft")；fail
（release_notes.py:47-50）向标准错误打印并返回 1。该校验位于
release_notes.py:163 的文件存在性检查之前，全程未调用
sqlite3.connect，故数据库文件不存在也优先报此错，且不创建文件。
对应 README.md:90-92。

5.2 同样得到上述失败结果的情形（同一代码分支）

  - 空值：        --prefix ""        （is_blank 判空串）
  - 仅含空白的值：--prefix "   "     （isspace 判定，含换行等空白字符）
  - 重复提供：    --prefix v1 --prefix v2
                                     （len(prefixes) != 1，
                                      release_notes.py:155）
  三者均退出码 1、标准输出为空、标准错误仅 Invalid draft 加换行；即使
  数据库文件不存在也优先报此错，且不创建数据库文件。

5.3 成功但输出空数组 [] 的情形（退出码 0，标准错误为空）

  下列情形标准输出均恰为 [] 加一个换行，且都不创建数据库或补建表：
  - 有效前缀无匹配项：如第四节样例库上 --prefix zz，筛选后 rows 为空
    （release_notes.py:181-183），items 为空（release_notes.py:188-191）。
  - 数据库文件不存在：--db missing.sqlite 且前缀有效（如 --prefix v1），
    第 2 步短路（release_notes.py:163），missing.sqlite 不被创建。
  - 有效 SQLite 文件但没有 drafts 表：第 3 步 has_table 为 None
    （release_notes.py:168-172），与空库等价。
  - drafts 表存在但表内无草稿：SELECT 返回空行集
    （release_notes.py:173-175），items 为空。
  对应 README.md:70-71、88-89。

5.4 未约定情形

  数据库文件已损坏（存在但不是有效 SQLite 文件）等情形，README 与源码
  注释均未约定其行为：sqlite3.connect 或查询可能抛出异常，不能推定为
  输出空结果 []。本文不对未约定情形作任何断言。
