--------------------------------------------------------------------------------

示例数据（本次核对虚构）：
  版本名：0.1.0
  标题：  首次草稿
  变更1：新增草稿创建入口
  变更2：支持按版本名查看

说明：命令行中的引号由 shell 解释，程序通过 argparse 收到的是去掉外层
引号后的字符串本身；程序内部不再做引号处理。

2.1 创建（符合 README.md:17-19 的公开用法）

  python release_notes.py --db notes.sqlite create 0.1.0 \
    --title "首次草稿" \
    --change "新增草稿创建入口" \
    --change "支持按版本名查看"

按源码逐阶段行为：
  (1) argparse 收集：args.version="0.1.0"，args.title="首次草稿"，
      args.change=["新增草稿创建入口", "支持按版本名查看"]
      （append 顺序即传入顺序；release_notes.py:132-137、43）。
  (2) 有效性校验：release_notes.py:48-55。四项条件全部不命中（版本名非空白、
      标题非 None 且非空白、变更列表非空、逐条非空白），继续执行。
  (3) 连接并建库建表：release_notes.py:57-59。notes.sqlite 不存在则由
      sqlite3.connect 创建；executescript 建立 drafts、changes 两表。
  (4) 查重：release_notes.py:62-66，SELECT 1 FROM drafts WHERE version=?，
      参数化绑定 "0.1.0"；新库无此行，继续。
  (5) 写入（同一事务 with conn，release_notes.py:61）：
      - release_notes.py:68-71 插入 drafts 一行：("0.1.0", "首次草稿")。
      - release_notes.py:72-79 executemany 插入 changes 两行，
        position 由 enumerate(changes) 生成（release_notes.py:77），从 0 起：
          ("0.1.0", 0, "新增草稿创建入口")
          ("0.1.0", 1, "支持按版本名查看")
      - 退出 with 块无异常，事务提交。
  (6) 输出：release_notes.py:86 print(f"Created {args.version}")，
      release_notes.py:87 return 0。

  静态推演结果：退出码 0；标准输出恰好一行：
      Created 0.1.0
  标准错误无输出。与 README.md:26 的公开约定一致。

2.2 查看（可在本进程退出后的新进程中，用同一 --db 路径执行）

  python release_notes.py --db notes.sqlite show 0.1.0

按源码逐阶段行为：

  (2) release_notes.py:97-99：SELECT title FROM drafts WHERE version=?，

      标题即从 drafts.title 读回（release_notes.py:102）。
  (3) release_notes.py:104-111：SELECT content FROM changes

      读回，顺序由 changes.position 决定。
  (4) 拼装输出：release_notes.py:116-118，

      每条变更加 "- " 前缀，sys.stdout.write 以 "\n" 连接并在末尾补一个 "\n"。

  静态推演结果（退出码 0，标准输出，行序如下）：
      Version: 0.1.0
      Title: 首次草稿
      - 新增草稿创建入口
      - 支持按版本名查看
  与 README.md:39-46 的格式约定一致。

三、两个边界分支
--------------------------------------------------------------------------------

3.1 重复版本名

  触发条件（源码可证）：
  - 同一 --db 数据库的 drafts 表中已存在 version 等于传入文本的行，
    SELECT ... fetchone() 非 None（release_notes.py:62-65）。比较规则同
    2.3（精确、区分大小写）。
  - 兜底条件：并发进程抢先插入同主键版本时，INSERT drafts 触发
    sqlite3.IntegrityError（PRIMARY KEY 冲突），被 release_notes.py:80-82
    捕获（该分支为代码静态可见，并发时机未实际运行验证）。

  实际结果：
  - 返回 1（release_notes.py:66、82）；
  - 标准错误输出（fail 定义于 release_notes.py:36-39，写 sys.stderr）：
      Version already exists: 0.1.0
  - 标准输出无 "Created ..."（release_notes.py:86 不会执行）。
  - 与公开约定 README.md:30-31 一致（退出码 1、该消息、不覆盖旧标题或条目）。

  失败后是否留下版本记录或条目：
  - 不新增该版本的任何行：命中 SELECT 后在任何 INSERT 之前返回
    （release_notes.py:65-66 先于 68-79）。
  - 旧版本的 drafts 行与 changes 行不在本事务内修改，保持原样。
  - IntegrityError 路径中 with conn（release_notes.py:61）回滚本事务，
    不留部分数据（release_notes.py:80-82 注释明示）。
  - 附注（文件层面，非版本记录层面）：数据库文件与两张表的结构创建于
    release_notes.py:57-59，在查重之前；但“版本名已存在”这一情形本身
    以旧版本存在为前提，即该文件和表此前已建立，本次失败不改变其内容。

  用同一组示例的静态推演：
    python release_notes.py --db notes.sqlite create 0.1.0 \
      --title "重复版本" --change "不应写入"
    # 退出码 1；stderr：Version already exists: 0.1.0
  随后 show 0.1.0 的输出与 2.2 完全相同，标题仍为“首次草稿”，
  仍为原来的两条、顺序不变（与 README.md:86-92、102 的示例一致）。

3.2 空变更条目

  触发条件（源码可证），空白判定函数 is_blank：text == "" 或 text.isspace()
  （release_notes.py:31-33），即空字符串，或仅由 Python 认定的空白字符
  （空格、制表、换行、全角空格等）组成。校验组合见 release_notes.py:48-55：
  - 完全未提供 --change：args.change 为 None，changes 取空列表
    （release_notes.py:43），not changes 为真（release_notes.py:52）；
  - --change ""：空字符串，any(is_blank(...)) 命中（release_notes.py:53）；
  - --change "   "（或纯制表/换行）：str.isspace() 为真，同样命中。
  （同一校验分支还覆盖版本名为空/纯空白、--title 缺失即 None、
    标题为空/纯空白：release_notes.py:49-51。这是源码现状，不另立语义。）

  实际结果：
  - 返回 1（release_notes.py:55）；
  - 标准错误输出：Invalid draft
  - 标准输出无 "Created ..."。
  - 与公开约定 README.md:27-29 一致。

  失败后是否留下版本记录或条目：
  - 不留下，且通常连数据库文件都不会新建：整个校验位于
    sqlite3.connect（release_notes.py:57）之前，注释 release_notes.py:45-47
    明示“校验发生在连接数据库之前，失败时不会新建数据库文件”。
    失败路径执行不到任何 SQL，无表、无 drafts 行、无 changes 行。
  - 若 notes.sqlite 此前已存在，本进程根本不打开它，其已有内容不变。
  - 与公开约定 README.md:27-28“不会创建文件或留下部分草稿”一致。

  用同一组示例的静态推演（两种空条目形态）：
    python release_notes.py --db notes.sqlite create 0.2.0 \
      --title "空串条目" --change ""
    # 退出码 1；stderr：Invalid draft；notes.sqlite 若此前不存在则不被创建

    python release_notes.py --db notes.sqlite create 0.2.0 \
      --title "空白条目" --change "   "
    # 退出码 1；stderr：Invalid draft；同上
  因此 2.1 创建的 0.1.0 不受任何影响，show 结果仍与 2.2 相同。

  另需区分的参数缺失情形（源码可知，README 未展开）：
  若连参数本身都缺（如不给 --db、不给版本名位置参数、不给 create/show
  子命令），argparse 在 release_notes.py:152 解析阶段直接报错退出，
  退出码为 argparse 标准的 2，不会进入 cmd_create/cmd_show；
  这与“给了参数但值为空/空白”得到的退出码 1（Invalid draft）不同。
  README 的退出码约定只描述进入业务逻辑后的 0/1 两种结果。
